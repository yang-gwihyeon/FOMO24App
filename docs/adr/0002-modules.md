# ADR-0002 FOMOCore / MarketKit / 앱 3계층 모듈 분리

## 맥락
초기엔 단일 타깃. 위젯이 모델을 공유해야 했고, 시세 파싱·시장시간 계산은 네트워크 없이 테스트하고 싶었다.

## 선택지
| | 장점 | 단점 |
|---|---|---|
| (a) 단일 타깃 + 폴더 | 간단 | 위젯과 코드 공유 불가, 테스트가 앱 전체 빌드에 묶임 |
| (b) 기능별 모듈(Feature modules) | 팀 확장에 유리 | 1인 프로젝트엔 과함, 경계 관리 비용 |
| (c) **계층별 3모듈** | 위젯 공유, 순수 로직 격리, 빌드 병렬화 | 경계 위반을 사람이 지켜야 함 → 린트로 보완 |

## 결정
(c). 의존은 단방향: 앱 → MarketKit → FOMOCore, 위젯 → FOMOCore. FOMOCore는 시스템 프레임워크만.
경계 위반은 `.swiftlint.yml` 커스텀 규칙(`no_firebase_in_core`, `no_urlsession_in_views`)으로 기계 검사.

## 결과
- 모듈 테스트(`make test`)는 앱·Firebase 없이 실행. 27개 테스트, 네트워크 0.
- 위젯·라이브액티비티가 FOMOCore 모델을 그대로 사용.
- (측정 예정 B5) 모듈별 빌드 시간.

## 재검토 조건
기능이 늘어 앱 타깃이 비대해지면 Feature 모듈 도입 검토.
