# ADR-0006 시세 갱신은 5초 폴링 (웹소켓 보류)

## 맥락
4개 거래소 시세를 포그라운드에서 갱신해야 한다. 거래소마다 웹소켓 프로토콜·재연결 규칙이 다르다.

## 선택지
| | 장점 | 단점 |
|---|---|---|
| (a) **5초 폴링, 포그라운드만** | 구현 단순, 4개 소스 동일 코드 경로, 실패 격리 쉬움 | 분당 48요청, 지연 최대 5초 |
| (b) 웹소켓 | 실시간, 요청 수 감소 | 소스별 프로토콜 4종, 재연결·백오프·하트비트, 배터리 상시 연결 |
| (c) 적응형 폴링 | (a)의 단순함 + 요청 수 감소 | 화면 상태 추적 필요 |

## 결정
(a)로 출시. 백그라운드 진입 시 중단. 다이나믹 아일랜드는 서버 푸시로 보완.
**B3(네트워크·배터리) 기준선 측정 후** (c) → 필요 시 (b) 순으로 재검토.

## 결과
- 요청 수·바이트·Energy Log 기준선: 미측정 (docs/perf 에 기록 예정).

## 재검토 조건
B3 측정에서 배터리 영향이 눈에 띄거나, 사용자가 5초 지연을 체감하는 피드백이 있을 때.
