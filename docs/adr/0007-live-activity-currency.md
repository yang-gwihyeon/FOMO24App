# ADR-0007 라이브 액티비티 표시 통화는 시작 시점에 고정 (환산은 위젯)

## 맥락
앱은 통화 칩(USD·KRW·JPY·EUR·GBP)으로 시세를 환산해 보여주지만, 다이나믹 아일랜드·잠금화면
라이브 액티비티는 항상 `$`로만 표시됐다. 액티비티 `ContentState`는 서버 Cloud Function이
1분마다 APNs로 직접 갱신하며, 서버는 USD 가격만 보낸다 (`Stock24-backend/functions/index.js`).
위젯 익스텐션은 앱의 `PriceStore`(선택 통화·환율)를 읽을 수 없다.

## 선택지
| | 장점 | 단점 |
|---|---|---|
| (a) **통화·환율을 `ActivityAttributes`에 고정, 위젯이 USD→현지 환산** | 앱만 수정, 서버 배포 불필요, 기존 푸시 페이로드 호환 | 환율이 시작 시점(최대 8시간)으로 고정 |
| (b) 서버가 통화별 환산 가격을 `ContentState`로 푸시 | 환율 실시간 | `laTokens` 문서에 통화 저장 + 함수가 FX도 조회·환산 + 배포, 페이로드 변경으로 구·신 앱 호환 처리 필요 |
| (c) `ContentState`에 선택적 `fxRate` 추가, 앱 갱신 시만 채움 | 포그라운드에선 실시간, 백그라운드는 (a)로 폴백 | 표시 환율이 앱 상태에 따라 오락가락, 코드 경로 2개 |

## 결정
(a). 판단 기준은 **서버 무변경**과 **한 코드 경로**.
원·엔·유로·파운드의 일중 변동은 대부분 1% 미만이고, 아일랜드 컴팩트 뷰는 등락률만 보이므로
8시간 고정 환율이 체감 오차를 만들지 않는다.
- 환산 로직은 `Currency.convert(usd:rate:)` 하나로 두고 앱(`PriceStore`)·위젯이 공유한다.
- 환율이 없는 비USD 통화로 시작하면 USD로 시작한다 — `₩` 기호에 달러 숫자가 붙는 오표시를 막기 위해.
- 구버전(통화 필드 없는) 액티비티도 `decodeIfPresent`로 USD 기본값으로 복원되어 앱 업데이트 직후 `restore()`가 실패하지 않는다.

## 결과
- FOMOCore 테스트 9개 추가 (환산 방향·폴백·구버전 JSON 복원·왕복 인코딩).
- 서버·위젯 타임라인(`PriceWidget`)은 변경 없음 — 홈 위젯은 여전히 USD.

## 재검토 조건
사용자가 아일랜드 가격과 앱 가격의 환율 차이를 체감한다는 피드백이 있거나, 홈 위젯에도 통화 선택이
필요해져 App Group 공유 저장소를 도입할 때 (그때 (c) 또는 App Group 기반으로 재설계).
