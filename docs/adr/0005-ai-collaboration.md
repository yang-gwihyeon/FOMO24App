# ADR-0005 AI 에이전트 협업 방식: 기준은 사람, 초안은 AI

## 맥락
Claude Code로 구현 속도는 올랐지만, "왜 그렇게 했는지"를 설명할 수 없는 변경이 쌓일 위험이 있었다. 1인 개발이라 리뷰어도 없었다.

## 선택지
| | 장점 | 단점 |
|---|---|---|
| (a) AI에 자유롭게 위임 | 빠름 | 결정 근거 소실, 회귀 위험 |
| (b) AI 사용 금지 | 통제 | 속도 손실, 비현실적 |
| (c) **역할 분담 + 기록 강제** | 속도와 설명 가능성 둘 다 | 문서화 비용 |

## 결정
(c). 사람은 문제 정의·판단 기준·측정·최종 판단, AI는 선택지·초안·리뷰 코멘트.
강제 장치:
1. `CLAUDE.md` — AI가 따라야 할 프로젝트 규칙 (사람 온보딩 문서와 동일).
2. PR 템플릿 6칸(관찰·가설·선택지·결정·측정·배운 것) — 비면 머지 금지.
3. `.swiftlint.yml` — 리뷰 문서를 기계 규칙으로. AI도 사람도 같은 게이트.
4. `.claude/settings.json` 훅 — 편집 후 포맷, 커밋 전 시크릿 검사.
5. 성능 변경은 측정 전 금지 (`docs/perf/`).

## 결과
- 모든 변경에 "왜"가 PR에 남는다. 면접 답변 = PR 본문.
- (측정 예정) PR당 카드 완성률, 린트 위반 추이.

## 재검토 조건
팀에 합류해 기존 리뷰 프로세스가 있으면 그쪽에 맞춘다.
