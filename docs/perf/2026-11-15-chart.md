# 차트 시트 (기간 차트 + 실시간 1초 차트) — 성능·호출량 점검

## 관찰   도구 · 수치 · 재현 절차
조건: iPhone 시뮬레이터 · Debug 구성 · NVDA · Wi‑Fi. 실행 12초 뒤부터 `top -pid <앱> -l 16 -s 2`로 30초(15표본) 측정.
**실기기·Release·Instruments 측정이 아니다** — 상대 비교용이며 B0 기준선을 대체하지 않는다.

| 화면 | 평균 CPU | 최대 CPU | 메모리 |
|---|---|---|---|
| 마켓 목록만 (5초 폴링) | 1.7% | 5.6% | 51MB |
| 차트 1주 (168점) | 1.9% | 5.3% | 57MB |
| 차트 1일 (289점) | 2.0% | 6.2% | 57MB |
| 차트 실시간 (1초 갱신) | 3.1% | 6.2% | 57MB |

호출량 (코드 리딩 + 실제 호출로 확인):
- 차트 1회 열기 = `candleSnapshot` 1요청. 응답 0.8KB(실시간)~39KB(1일), 0.13~0.35초.
- 실시간 탭 = WebSocket 연결 1개 · 구독 1개(`activeAssetCtx`), 수신 초당 약 1건.
- Firebase(Firestore·Functions) 호출 없음. Analytics 이벤트(`chart_open`, `chart_range`, `fomo_add`)만 추가.
- 거래소 한도(Hyperliquid 문서, IP당): REST 가중치 1200/분, info 요청 20(+candleSnapshot은 60개당 추가, 양은 문서에 없음),
  WebSocket 동시 10개 · 새 연결 30개/분.
- 기존 5초 폴링이 Hyperliquid에 분당 36요청(주식·코인·환율 각 12회) ≈ 가중치 720/분을 이미 쓰고 있어 **남는 여유는 약 480/분**.

## 가설
1. 렌더: 실시간 탭은 1초마다 시트 전체 body가 다시 돈다 → CPU가 눈에 띄게 오를 수 있다.
2. 호출: 코인은 주식 dex를 먼저 찔러 보고(HTTP 500) 다시 요청해 매번 2요청 → 여유 480을 빨리 깎는다.
3. 호출: 연결 실패 시 2초 고정 재시도 = 분당 30회 = 새 연결 한도와 정확히 같다 → 오프라인이 길면 복구 후에도 못 붙는다.
4. 배터리: 백그라운드로 가도 실시간 연결과 1초 타이머가 살아 있다.

## 선택지 (최소 2개, 트레이드오프)
- 가설 1: (a) 그대로 둔다 (b) 차트만 별도 `@Observable`로 분리해 body 범위를 줄인다 — 코드 복잡도 증가.
- 가설 2: (a) 종목 종류를 `ChartStore`에 기억 (b) Catalog에 종류 필드 추가 — 원격 카탈로그 스키마 변경 필요.
- 가설 3: (a) 지수 백오프 2→30초 (b) 재시도 횟수 제한 후 수동 재연결 버튼 — 사용자가 직접 눌러야 함.
- 가설 4: (a) `scenePhase`가 active일 때만 구독 (b) 그대로 두고 iOS의 일시중단에 맡김 — 복귀 시 빈 구간이 직선으로 이어짐.

## 결정   판단 기준 명시
- 가설 1 → (a). 실시간 +1.4%p(1.7→3.1%)는 목록 화면의 순간 최대(5.6%)보다 낮다. 측정상 문제가 없으므로 고치지 않는다.
- 가설 2 → (a). 스키마를 건드리지 않고 두 번째 요청부터 1요청으로 줄어든다.
- 가설 3 → (a). 자동 복구를 유지하면서 한도를 넘지 않는다 (최악 분당 약 5회).
- 가설 4 → (a). 복귀 시 실시간 창을 새로 깐다.

## 측정   전 → 후 (같은 절차·같은 기기·같은 빌드 구성)
- 코인 차트 열기: 2요청 → 첫 회 2요청, 이후 1요청 (코드 경로 기준, 계측 도구로 세지는 않음).
- 재연결: 30회/분 → 최대 약 5회/분 (2,4,8,16,30,30…초).
- 백그라운드: 설정 앱으로 나갔다 돌아온 뒤 `LIVE` 재표시 + 창이 새로 깔리는 것을 스크린샷으로 확인.
- CPU·메모리는 수정 후 재측정하지 않았다 (렌더 경로를 바꾸지 않음).

## 배운 것
- 한도는 서버가 아니라 **사용자 IP**마다 걸린다 → 사용자 수가 늘어도 한도·비용이 합산되지 않는다. 대신 같은 공유기를 쓰는 사용자끼리는 한도를 나눠 쓴다.
- 차트보다 기존 5초 폴링이 한도의 60%를 쓰고 있다. 환율은 5초마다 받을 필요가 없어 보인다 — README의 P3와 함께 따로 다룰 것 (이번에는 손대지 않음).
- 아직 안 본 것: 실기기 Release에서의 에너지 등급, 실시간 탭 30분 방치 시 메모리 기울기.
