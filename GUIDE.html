5. Swift 6 & Strict Concurrency — 지켜야 할 규칙

전 타깃이 SWIFT_VERSION 6.0 + SWIFT_STRICT_CONCURRENCY complete입니다. 새 코드를 쓸 때 이 원칙을 따르면 컴파일러가 데이터 레이스를 잡아줍니다:

  • 전역 가변 상태는 @MainActor로 격리 — MarketSession.all, Fmt 포매터 캐시, AlertSettings가 이 패턴입니다.
  • 모델 값 타입은 Sendable 명시 — public 타입은 자동 추론이 안 되므로 StockFuture처럼 직접 선언합니다.
  • 외부 SDK 델리게이트는 nonisolated로 받고 Task { @MainActor in }으로 홉 — FirebaseSync.messaging(_:didReceiveRegistrationToken:) 참고.
  • non-Sendable SDK 타입(예: ActivityKit Activity)은 API 자체가 스레드 세이프한 경우에 한해 nonisolated(unsafe) + 주석으로 명시 — LiveActivityManager 참고. 남용 금지.
이번 마이그레이션에서 실제 수정한 곳은 4곳뿐이었습니다: FirebaseSync(델리게이트 격리) · CalendarStore(@MainActor 누락) · AlertSettings(격리 상속) · LiveActivityManager(Activity 전송). 기존 코드가 @MainActor @Observable 패턴을 잘 따르고 있었기 때문입니다.

6. 인터랙티브 위젯 (App Intents)

홈 화면 위젯 우하단에 새로고침 버튼(↻)이 생겼습니다. 탭하면 앱을 열지 않고 위젯 프로세스 안에서 RefreshPricesIntent.perform()이 실행되어 최신 시세로 타임라인을 다시 로드합니다 (iOS 17+ 인터랙티브 위젯).

// Widgets/PriceWidget.swift
struct RefreshPricesIntent: AppIntent {
    static let title: LocalizedStringResource = "Refresh Price"
    func perform() async throws -> some IntentResult {
        WidgetCenter.shared.reloadTimelines(ofKind: "PriceWidget")
        return .result()
    }
}
// 뷰에서: Button(intent: RefreshPricesIntent()) { Image(systemName: "arrow.clockwise") }

기존 종목 선택(SelectTickerIntent)도 App Intents 기반이라, 위젯 전체가 AppIntents 표준을 따릅니다. 시뮬레이터/기기에서 위젯을 다시 추가해야 버튼이 보일 수 있습니다.

7. CI — GitHub Actions

.github/workflows/ci.yml — main 푸시와 모든 PR에서 자동 실행:

  1. Xcode(latest-stable) 선택 → brew install tuist
  2. CI용 더미 plist 복사 — CI/GoogleService-Info.example.plist → 루트 (실키는 저장소에 없으므로)
  3. SPM 의존성 캐시 → tuist generate
  4. 모듈 유닛테스트 (Modules 스킴, 시뮬레이터)
  5. 앱 전체 빌드 (서명 없이 시뮬레이터용)

로컬에서 CI와 동일한 검증을 돌려보려면 위 3장의 CLI 명령 두 개를 순서대로 실행하면 됩니다.

8. Firebase 키 보안

GoogleService-Info.plist는 이제 git에 없습니다 — .gitignore 처리 + git filter-branch로 과거 커밋 히스토리에서도 완전히 제거했습니다. 로컬 파일은 그대로 있어 빌드에는 영향이 없습니다.

주의: 히스토리를 다시 쓴 상태라 원격 반영에는 force push가 1회 필요합니다 (아래 9장). 새 기기에서 클론하면 Firebase 콘솔에서 plist를 다시 받아 루트에 넣어야 합니다.

9. 남은 수동 단계 (1회성)

  1. Force push — 히스토리 재작성 반영: 
    cd ~/Desktop/0404/FOMO24App
git push --force origin main
  2. 공개 전환(선택) — 포트폴리오로 쓰려면 GitHub 저장소 Settings → Change visibility → Public. plist가 히스토리에서 제거된 뒤이므로 안전합니다. 단, Firestore 보안 규칙이 잠겨 있는지 먼저 확인하세요.
  3. CI 확인 — 푸시 후 GitHub 저장소의 Actions 탭에서 첫 워크플로가 초록불인지 확인.

10. 면접에서 이렇게 설명하세요

  • 왜 모듈화? — "도메인(FOMOCore)과 외부 연동(MarketKit)을 분리해 테스트 가능한 경계를 만들었다. 거래소 API 4종이 프로토콜(PriceService) 하나로 추상화되어 있어 목업 주입으로 스토어 로직을 검증한다."
  • 왜 Tuist? — "프로젝트 파일 충돌 제거 + 타깃 정의를 코드 리뷰 가능한 Swift로 관리. 카카오뱅크·29CM 등이 쓰는 방식과 동일."
  • Swift 6 경험 — "전역 가변 상태를 @MainActor로 격리하고, SDK 델리게이트 콜백은 nonisolated → 메인 액터 홉으로 처리. 컴파일 타임에 데이터 레이스를 차단했다."
  • CI — "실키 없이 빌드되도록 더미 설정 파일 주입 단계를 뒀고, 모듈 테스트(수 초)와 앱 빌드를 분리해 피드백 속도를 챙겼다."
